# 翻訳こんにゃくモード UI 仕様書

> **本文書の目的**: 翻訳こんにゃくモード（双方向同時翻訳機能）の UI 仕様を、
> 「ユーザーがこの要素を操作したら、こう動くのが常識的」という期待動作の集合体としてまとめる。
>
> 現状の実装挙動を追認する仕様ではなく、**あるべき姿** を記述している。
> 現状の実装との差分は §11「現状の実装と差分（バグ候補）」に列挙する。

## 0. 用語

- **系統1（route_a）** = 相手→自分（聞き取り字幕）。相手の発話を自分が理解するための翻訳経路。
- **系統2（route_b）** = 自分→相手（同時通訳）。自分の発話を相手に伝えるための翻訳経路。
- **アプリ状態**:「停止中」「稼働中」「停止処理中」「エラー」
- **系統状態**:「有効」「無効（チェックOFF）」

## 2. ボタン仕様

### 2.1「翻訳こんにゃくモードプリセット」ボタン

- **押下時の期待動作**（設定のみ適用。起動はしない）:
  - 系統1: 入力デバイス = デバイスリスト中、最初の `[Loopback]` を含むデバイス / 翻訳先言語 = 日本語 / 音声出力 = OFF
  - 系統2: 入力デバイス = デバイスリスト中、最初の非Loopbackデバイス（マイク）/ 翻訳先言語 = English / 音声出力 = ON / 出力デバイス = 名前に "cable input"（大小文字問わず）を含む最初のデバイス
  - 上記いずれかの候補が存在しない場合は、該当コンボの変更をスキップする（エラーにしない）
  - 適用後、系統1・系統2の有効チェックは変更しない（現状のまま維持）
- **押下できる状態**: 停止中・稼働中どちらでも押下可
- **稼働中に押下した場合**: 設定値は変わるが、稼働中の系統には即時反映しない。次回起動時から反映される
- **副作用**: なし（設定変更のみ。ファイルへの保存はしない）
- **ログ**: `[USER] 翻訳こんにゃくモードプリセットボタン押下`

### 2.2「開始/停止」ボタン（TAG_KONNYAKU_START_BTN）

**停止中（ラベル「開始」）に押下した場合**:

- 両系統が OFF（チェック無効）ならステータスバーに「少なくとも1つの系統を有効にしてください」を表示し、起動しない
- 有効な系統のデバイスが解決できない（リスト上に存在しない）場合は起動しない。**ユーザーへのフィードバック（ステータスバーへのエラー表示）が必要**
- 上記チェックを通過したらMultiCaptionSystemを起動し、ボタンラベルを「停止」に変える
- ステータスバーに起動成功/失敗を表示する
- 起動中（ラベルが「停止」になるまで）はボタンを再押下不可とする

**稼働中（ラベル「停止」）に押下した場合**:

- 即座にボタンを「停止中...」表示 + disabled に変える（UIフリーズ防止）
- バックグラウンドスレッドでshutdownを実行
- shutdown完了後、ボタンを「開始」表示 + enabled に戻す
- ステータスバーに「停止しました」を表示する

**押下できない状態**:

- 停止処理中（ラベル「停止中...」、disabled）

**ログ**: `[USER] 開始ボタン押下 (running=False)` / `[USER] 停止ボタン押下 (running=True)`

### 2.3「両方 ON」ボタン

- **押下時の期待動作**: 系統1・系統2の有効チェックボックスを両方 ON にする
- **稼働中に押下した場合**: チェック状態は変わるが、稼働中の系統には即時反映しない（§3.1 参照）
- **ログ**: `[USER] 両方 ON ボタン押下`

### 2.4「両方 OFF」ボタン

- **押下時の期待動作**: 系統1・系統2の有効チェックボックスを両方 OFF にする
- **稼働中に押下した場合**: チェック状態は変わるが、稼働中の系統には即時反映しない（§3.1 参照）
- **ログ**: `[USER] 両方 OFF ボタン押下`

### 2.5「ログクリア」ボタン

- **押下時の期待動作**: ログエリアの全テキストを削除する
- **押下できる状態**: 常時（停止中・稼働中どちらでも）
- **副作用**: ログファイル（console_*.log）の内容は消さない。GUI表示のみクリア
- **ログ**: なし（ログクリア自体をログに残す必要はない）

### 2.6「Verbose」ボタン（トグル）

- **OFF状態（表示: "Verbose ○"）に押下**: ON に切り替え、ラベルを「Verbose ●」にする
- **ON状態（表示: "Verbose ●"）に押下**: OFF に切り替え、ラベルを「Verbose ○」にする
- **稼働中の場合**: 稼働中のシステムにも即時反映される（verboseログが増える）
- **設定保持**: 設定ファイルに保存され、次回起動時に状態が復元される
- **ログ**: なし（状態はボタンラベルが示す）

### 2.7「表示/非表示」ボタン（APIキー用）

- **「表示」に押下**: テキストのパスワードマスクを解除し、ラベルを「非表示」に変える
- **「非表示」に押下**: テキストをパスワードマスクし、ラベルを「表示」に変える
- OpenAI用・DeepL用それぞれ独立して動作する

### 2.8「保存」ボタン（APIキー）

- **入力が両方空の場合**: キー状態テキストに「キーが未入力です」を表示し、保存しない
- **保存成功 + 停止中**: キー状態テキストに「保存しました」を表示。翻訳エンジンのコンボを再構築し、開始ボタンを有効化
- **保存成功 + 稼働中**: キー状態テキストに「変更は次回起動時に反映されます」を表示
- **保存失敗**: キー状態テキストに「保存に失敗しました」を表示

## 3. チェックボックス仕様

### 3.1 系統1 有効チェックボックス（TAG_ROUTE_A_ENABLE）

- **ON 時の期待動作**:
  - 系統1が起動対象になる（次回「開始」押下時に系統1のCaptionSystemが起動される）
  - 視覚的に: 系統1セクションのコントロール類が通常色（操作可能）で表示される
- **OFF 時の期待動作**:
  - 系統1が起動対象から外れる
  - 視覚的に: 系統1セクションのコントロール類が灰色化（disabled）する
  - 入力レベルメーターが0%になる
  - 出力レベルメーターが0%になる
  - ログエリアに系統1の翻訳結果が出なくなる
- **稼働中にチェックを変更した場合**:
  - **次回起動時から反映**（稼働中の系統を即座に停止させない）
  - 稼働中にOFFにしても、現在動いている系統1は起動中のまま維持される
  - ステータスバーに「系統1は次回起動時から無効になります」等のヒントを表示する（任意）
- **「両方 OFF」時の特別ルール**: 開始ボタンを押そうとするとエラーになる（§2.2参照）
- **ログ**: `[USER] 系統1 有効チェック ON` / `[USER] 系統1 有効チェック OFF`

### 3.2 系統2 有効チェックボックス（TAG_ROUTE_B_ENABLE）

- 系統1と対称。系統ラベルが「系統2」になる。
- **ログ**: `[USER] 系統2 有効チェック ON` / `[USER] 系統2 有効チェック OFF`

### 3.3 系統1 音声出力チェックボックス（TAG_ROUTE_A_OUTPUT_ENABLE）

- **ON 時の期待動作**:
  - 出力デバイスコンボで選択中のデバイスへ音声出力を開始する
  - 稼働中の場合は即時反映（`set_output_device(index)` が呼ばれる）
  - 出力デバイスが「(なし)」の場合は、チェックはONになるが音は出ない（エラーにしない）
  - 出力レベルメーターが動き始める（稼働中かつ系統1有効の場合）
- **OFF 時の期待動作**:
  - 音声出力を停止する
  - 稼働中の場合は即時反映（`set_output_device(None)` が呼ばれる）
  - 出力レベルメーターが0%になる
- **ログ**: `[USER] 系統1 音声出力 ON` / `[USER] 系統1 音声出力 OFF`

### 3.4 系統2 音声出力チェックボックス（TAG_ROUTE_B_OUTPUT_ENABLE）

- 系統1と対称。
- **ログ**: `[USER] 系統2 音声出力 ON` / `[USER] 系統2 音声出力 OFF`

## 4. コンボボックス仕様

### 4.1 系統1 入力デバイスコンボ（TAG_ROUTE_A_DEVICE_COMBO）

- **表示内容**: WASAPI デバイスの一覧（デフォルトは最初の `[Loopback]` デバイス）
- **変更時の期待動作**:
  - 停止中: 選択値を保持するのみ。次回起動時から反映
  - 稼働中: **設定値は変わるが、稼働中の系統1には即時反映しない**。次回起動時から反映
  - ステータスバーに「入力デバイスの変更は次回起動時から反映されます」等のヒントを表示する（任意）
- **ログ**: `[USER] 系統1 入力デバイス選択: <デバイス名>`（現状未実装、仕様として要追加）

### 4.2 系統2 入力デバイスコンボ（TAG_ROUTE_B_DEVICE_COMBO）

- 系統1と対称。デフォルトは最初の非Loopbackデバイス（マイク）。
- **ログ**: `[USER] 系統2 入力デバイス選択: <デバイス名>`（現状未実装）

### 4.3 系統1 入力ゲインモードコンボ（TAG_ROUTE_A_GAIN_MODE）

- **選択肢**: `off` / `manual` / `auto`
- **変更時の期待動作**:

  - `off` / `auto` 選択時: 倍率スライダーが非表示または disabled になる
- **ログ**: `[USER] 系統1 入力ゲインモード変更: 'manual'`

### 4.4 系統2 入力ゲインモードコンボ（TAG_ROUTE_B_GAIN_MODE）

- 系統1と対称。
- **ログ**: `[USER] 系統2 入力ゲインモード変更: <値>`

### 4.5 系統1 翻訳先言語コンボ（TAG_ROUTE_A_LANG_COMBO）

- **選択肢**: SUPPORTED_LANGUAGES テーブルから生成（現在: 日本語 / English）
- **変更時の期待動作**:
  - 停止中: 値を保持するのみ。次回起動時から反映
  - 稼働中: **即時反映しない**。次回起動時から反映
- **ログ**: `[USER] 系統1 翻訳先言語選択: <表示名>`（現状未実装）

### 4.6 系統2 翻訳先言語コンボ（TAG_ROUTE_B_LANG_COMBO）

- 系統1と対称。デフォルト = English。
- **ログ**: `[USER] 系統2 翻訳先言語選択: <表示名>`（現状未実装）

### 4.7 系統1 出力デバイスコンボ（TAG_ROUTE_A_OUTPUT_DEVICE_COMBO）

- **表示内容**: `(なし)` + 出力デバイス一覧。デフォルト = `(なし)`
- **変更時の期待動作**:
  - 稼働中 + 音声出力ONの場合: 即時反映（`set_output_device(index)` が呼ばれる）
  - 稼働中 + 音声出力OFFの場合: 値は変わるが出力は変わらない
  - 停止中: 値を保持するのみ
- **ログ**: `[USER] 系統1 出力デバイス選択: <デバイス名>`

### 4.8 系統2 出力デバイスコンボ（TAG_ROUTE_B_OUTPUT_DEVICE_COMBO）

- 系統1と対称。デフォルト = 名前に "cable input" を含む最初のデバイス（なければ `(なし)`）
- **ログ**: `[USER] 系統2 出力デバイス選択: <デバイス名>`

### 4.9 デバイスフィルタコンボ（TAG_HOST_API_COMBO）

- **選択肢**: `wasapi` / `all` / `mme` / `directsound`
- **変更時の期待動作**:
  - 入力デバイスコンボ・出力デバイスコンボの一覧を、選択したhost_apiで再列挙する
  - 系統1・系統2の入力デバイスコンボも再列挙対象とする（現状は単独モードのコンボのみ対象）
  - 設定ファイルに保存される
- **ログ**: なし

## 6. レベルメーター仕様

- **入力レベルメーター（系統1: TAG_LEVEL_METER_A_IN、系統2: TAG_LEVEL_METER_B_IN）**:
  - 動作条件: **稼働中 かつ 当該系統が有効（チェックON）** の場合のみ更新される
  - それ以外（停止中 / 当該系統チェックOFF）は 0% 固定で表示する
  - 色: 0〜60% = 緑、60〜85% = 黄、85〜100% = 赤
  - オーバーレイテキスト: `xx%` 形式で現在レベルを表示

- **出力レベルメーター（系統1: TAG_LEVEL_METER_A_OUT、系統2: TAG_LEVEL_METER_B_OUT）**:
  - 動作条件: **稼働中 かつ 当該系統が有効 かつ 音声出力チェックがON** の場合のみ更新される
  - それ以外は 0% 固定
  - 色・表示形式は入力レベルメーターと同様

## 7. 状態遷移

| 状態 | 開始/停止ボタン | 系統チェックの効果 | レベルメーター |
|---|---|---|---|
| 停止中 | ラベル「開始」、押下可 | 次回起動時の対象系統を決定 | 全て 0% |
| 稼働中（両系統有効） | ラベル「停止」、押下可 | チェック変更は次回起動時に反映 | 有効系統の入力・出力を動的更新 |
| 稼働中（片系統のみ有効） | ラベル「停止」、押下可 | 同上 | 有効系統のみ動的更新、無効系統は 0% |
| 停止処理中 | ラベル「停止中...」、disabled | 変更不可ではないが反映されない | 全て 0%（シャットダウン中） |
| エラー（API失敗等） | ラベル「開始」（停止後）または「停止」（継続中）| 状態による | 停止系統は 0%、継続系統は継続 |

## 8. エラー表示仕様

エラーはすべて **ステータスバー（TAG_STATUS_STATE）** に表示する。ダイアログポップアップは出さない。

| エラー種別 | 表示フォーマット | 対応するcategory |
|---|---|---|
| OpenAI クォータ超過 | `[系統1] ⚠️ OpenAI クォータ超過: ...` | `quota` |
| APIキー無効（認証失敗） | `[系統2] ⚠️ 認証エラー: APIキーを確認してください` | `auth` |
| レートリミット | `[系統1] ⚠️ レートリミット: しばらくお待ちください` | `rate_limit` |
| WebSocket接続失敗 | `[系統2] ⚠️ 接続失敗: ネットワークを確認してください` | `connection` |
| バックグラウンドスレッド異常終了 | `こんにゃく route-a スレッド異常終了: <例外型>: <メッセージ>` | — |
| 起動失敗（例外） | `こんにゃく起動失敗: <例外型>: <メッセージ>` | — |
| 両系統OFFで開始試行 | `少なくとも1つの系統を有効にしてください` | — |
| 入力デバイス未解決で開始試行 | `系統1 入力デバイスが選択されていません` 等 | — |

- エラー表示後、アプリは自動的に停止しない（継続可能な場合はそのまま稼働を続ける）
- 停止が必要な場合（スレッド異常終了等）は自動的に「停止」状態に戻す

## 9. 操作ログ仕様

すべてのユーザー操作を `stdout` に出力する（`console_*.log` に保存される）。

## 10. AI 自動デバッグ仕様（CLIフラグ）

### `--auto-konnyaku=N`

- GUIを起動後、バックグラウンドスレッドが以下の手順を自動実行する:
  1. 5秒待機（モデルロード待ち）
  2. プリセットボタン押下相当の処理を実行
  3. 開始ボタン押下相当の処理を実行
  4. N秒間待機（翻訳動作を確認）
  5. 停止ボタン押下相当の処理を実行
  6. GUIを閉じてアプリを終了
- ログから翻訳の成否・エラーの有無を確認するために使用する

### `--inject-test-transcripts`

- `--auto-konnyaku` と組み合わせて使用
- WS接続待機後（起動から3秒後）に、偽の transcript を両系統に注入する
- overlay.html への broadcast 経路（WebSocket送信）を実音声なしで検証するために使用する
- 注入内容（例示）: 系統1に英語テスト文、系統2に日本語テスト文

### `--verbose`

- 起動時から verbose モードを ON にする（通常のVerboseボタン押下と同等）
- RT_* イベントを詳細ログファイルに記録する

## 12. 未確定事項（監督確認が必要）

1. **稼働中の系統チェック切り替えの即時反映**: 仕様案では「次回起動時から反映」としたが、「稼働中に系統1チェックをOFFにしたら、今動いている系統1を即座に停止させる」という動作の方が望ましいか？ 即時反映にする場合、MultiCaptionSystemにroute単独のstop/restart APIが必要になる。

2. **稼働中の入力デバイス変更の即時反映**: 入力デバイス変更も稼働中に即時反映させるべきか？ 即時反映の場合、現在のRecorderを停止して新デバイスで再起動する必要がある。

3. **プリセットボタンを稼働中に押した場合の動作**: 現仕様では「設定値は変わるが稼働中の系統には反映しない」としたが、「稼働中はプリセットボタンを disabled にする」とする方が混乱が少いか？

4. **入力デバイス未解決時の開始エラー（B-07）**: サイレントリターンを修正する際、ステータスバーへの表示だけで十分か、それとも視覚的に目立つ警告（ボーダー色変更等）も必要か？

5. **ゲインスライダーの表示制御（B-09）**: `off`/`auto` 選択時は「非表示（`show=False`）」と「disabled」のどちらが望ましいか？ 非表示にすると行が詰まってレイアウトが崩れる可能性がある。

## 実装メモ（PRGちゃんへの引き継ぎ）

- **B-05（デバイスフィルタ再列挙）が最優先**: `_on_host_api_change` の中で `TAG_ROUTE_A_DEVICE_COMBO` と `TAG_ROUTE_B_DEVICE_COMBO` の `items` を更新していない。ここを追加修正するだけで解消する。
- **B-07（デバイス未解決のサイレントリターン）**: `_on_konnyaku_start_stop_click` の `if route_a_enabled and route_a_device is None: return` の直前に `dpg.set_value(TAG_STATUS_STATE, "系統1 入力デバイスが見つかりません")` を追加するだけでよい。
- **B-01/B-02（チェックOFF時のコントロール灰色化）**: `TAG_ROUTE_A_ENABLE` の `callback` が現状は `print` のみ。ここに `dpg.configure_item(TAG_ROUTE_A_DEVICE_COMBO, enabled=<bool>)` 等を追加する。灰色化する対象コントロールは系統1セクション内の全コントロール。
- **B-09（ゲインスライダー表示制御）**: 監督の確認（未確定事項5）を先に取ること。`show=False` か `enabled=False` かでコードが変わる。
- **監督確認事項1（系統チェック稼働中即時反映）が YESになった場合**: `MultiCaptionSystem` に `stop_route(route_id)` / `start_route(route_id)` の API を追加する必要がある。
- `_on_both_routes_on/off` で `set_value()` による値変更は DearPyGui の callback を自動発火しない。ログ出力やdisabled制御を両方ONボタン内でも明示的に呼び出す必要がある（B-10）。
- サンプル値・APIキー値はコードに絶対に埋め込まないこと。
