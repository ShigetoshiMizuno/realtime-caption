## Key Decisions & Rationale

- **base64 難読化を選択（暗号化ではない）** → 監督指示。実装シンプル、配布先で追加セットアップ不要。スクショ・casual 閲覧から守れれば十分というユースケース。本格的な機密性保護（DPAPI/Fernet/Keychain）は将来別 issue 化
- **session 制御に `session.` プレフィックス必須** → 実機エラーから判明。標準 Realtime API（プレフィックス無し）と translation エンドポイント（プレフィックス必須）で仕様が異なる
- **`session.input_transcript.*` 受信実装の必要性** → PR #7 の SPECちゃん類推実装で「API は原文を返さない」と判断していたが、公式ドキュメント再確認で誤りと判明。PR #26 で修正
- **デバイス重複は WASAPI 既定フィルタ採用** → 古いハード救済は `host_api: "all"` 設定で対応。汎用 -fake- インフィックス allowlist 拒否と同じ「安全側デフォルト + opt-in」哲学
- **動的表示制御は pure function 切り出し** → `_resolve_settings_visibility(trans_key) -> dict[str, bool]` をテスト可能に。GUI 直接更新ロジックと分離
- **Zoom プリセットボタンから visibility 明示呼び出し** → `dpg.set_value` はコールバック自動発火しないため、`_update_settings_visibility` を明示的に呼ぶ必要あり
- **マージ順序**: dotfiles → 独立 PR → PR #7 → PR #7 base の PR（#16/#13）の依存順
- **入力デバイス制限を撤廃** → VB-CABLE ユースケースでマイク入力が必須
- **PyAudio インスタンスを AudioOutputStream が所有** → CaptionSystem に責務を持たせると shutdown 順序が複雑になる
- **gitleaks の汎用 -fake- インフィックスを allowlist 拒否** → 攻撃者が `sk-realKey-test-...` で検出回避を狙うのを防ぐため
- **DeepL リーク後の filter-branch 採用** → git-filter-repo 未インストール、filter-branch + `--tree-filter` で sed 置換、`refs/original/` 削除、`reflog expire` + `gc --prune=now --aggressive`、force-with-lease で push
- **再発防止策を dotfiles に永続化** → SPEC/PRG/QA の各 agents/*.md に役割別ルール

## Key Learnings & Gotchas (長期記憶へ移行推奨)

- **Read ツールが credential ファイルを開くと値が会話全体に流れる**: Anthropic 内部 session のみだが、SPEC → PRG への転記で外部漏洩に繋がる連鎖を生む
- **TDD の RED コミットは git log で検証可能**: QA レビューで「テストファースト遵守」を機械的にチェックできる
- **API 仕様の類推実装は危険**: 公式ドキュメントが取得不可（402 等）でも、verbose ログで全イベントを保守的に記録すれば後で真実が判明する（Issue #23 の input_transcript 取りこぼしがその実例）
- **filter-branch は遅いが確実**: git-filter-repo が無くても代替可能。tree-filter + sed で履歴全体を書き換え
- **squash merge で base ブランチが消えた後の PR**: base を master に切り替え + merge コミットで master 側の進捗を取り込めば conflict 解消可能。`gh pr edit --base master` で実施
- **dotfiles の symlink 同期は方向性がファイルごとに違う**: agents/* は symlink で双方向同期、CLAUDE.md は別ファイル → 両方を手動同期する必要あり
- **gitleaks の汎用パターン allowlist は脆弱性**: `-fake-` / `-test-` などの汎用インフィックスを allowlist にすると、攻撃者が `sk-realKey-test-...` で回避を狙える
- **PyAudio の Host API**: Windows では同一物理デバイスが 3-4 個 (MME/DirectSound/WASAPI/Loopback) 列挙される。WASAPI 優先 + Loopback 別表記が現代的
- **GitHub Free plan の private repo 機能制限**: branch protection, rulesets, auto-merge が利用不可。Team plan ($4/user/月) で解放、個人 Pro は org repo に影響しない
- **DearPyGui の `dpg.set_value` は callback を自動発火しない**: 値変更後に動的処理が必要なら明示的に処理関数を呼ぶ
