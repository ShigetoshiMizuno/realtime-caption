## Key Decisions & Rationale

- **Case D アーキテクチャ採用（PTT 離脱後も Route B を RUNNING に維持）**
  - 旧設計: PTT 離脱 → `stop_route("b")` → `AudioOutputStream.stop()` → TTS キューを即破棄 → 音声途切れ
  - 新設計: PTT 離脱 → `close_audio_gate()` のみ → Route B RUNNING 維持 → TTS が最後まで再生
  - `start()` は idempotent（STARTING/RUNNING/STOPPING なら即 return）なので、次の PTT 押下時の `start_route("b")` 呼び出しは安全

- **`_ptt_latch_active` フラグを Python 側で管理**
  - DPG 2.1.1 の checkbox callback で `app_data` が OLD 値（クリック前の値）を返すバグを発見
  - `dpg.get_value(TAG_PTT_LATCH_CHECK)` は DPG 内部値（コールバック発火時点では更新済み）を返すので正しい
  - GUI 判定コードでは `dpg.get_value()` でなく Python フラグ `_ptt_latch_active` を参照する（コールバック経由でのみ更新される確実なフラグ）

- **`_is_ptt_pressing()` に音声ゲート判定を追加**
  - Case D で PTT 離脱後も Route B が RUNNING のまま残るため、旧判定（state == RUNNING）だと「押下中」と誤判定
  - `state in (STARTING, RUNNING) and _audio_gate == True` が「実際に送信中」の正しい定義

## Blockers, Gotchas & Workarounds

- **DPG 2.1.1 checkbox callback の `app_data` が旧値を返す**
  - 現象: チェックボックスを OFF→ON にクリックすると `app_data=False`（クリック前の値）が届く
  - 回避: コールバック内で `dpg.get_value(TAG_PTT_LATCH_CHECK)` を呼ぶ（DPG はコールバック発火前に内部値を更新する）
  - ただし LATCH-RESET などの非コールバックコンテキストでは `dpg.get_value()` が先行して True になりうるため、`_ptt_latch_active` Python フラグを正とする

- **Case D で Route B が RUNNING のまま残る → LATCH-RESET の条件が変わる**
  - 旧: `route_b_state not in (RUNNING, STARTING)` でラッチ自動リセット
  - 新: `route_b_state not in (RUNNING, STARTING, STOPPING)` — STOPPING 中もリセット除外してレースを防ぐ

- **`_update_ptt_visual_feedback` 内の自動再起動ロジック**
  - `route_b_sending=True`（ゲートON）かつ `route_b_state==IDLE` のとき自動で `start_route("b")` を呼ぶ
  - これは「ゲートが開いているのに Route B が止まってしまった」異常系の復旧

- **Flask/Click が bytes を stdout に書く**
  - `_TimestampedWriter.write()` の先頭に `isinstance(s, bytes)` チェックを追加して UTF-8 デコード
  - なかった場合: `TypeError: can only concatenate str (not "bytes") to str` で Flask スレッドがクラッシュ

## Key Learnings & Gotchas (長期記憶へ移行推奨)

- DPG 2.1.1 のチェックボックスコールバック: `app_data` は **クリック前の値**（OLD value）
  - `dpg.get_value()` を使うこと
- `AudioOutputStream.stop()` は即座にキューを破棄する。TTS 再生中は `stop()` を呼ばないこと
- `CaptionSystem.start()` は idempotent — STARTING/RUNNING/STOPPING なら即 return（二重起動安全）
