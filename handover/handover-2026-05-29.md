## Key Decisions & Rationale

- **PTT 常時 True 化（Q-SEM-4 確定）** → `_ptt_enabled` 変数削除、PTT 有効化チェックボックス廃止  
  理由: 「PTT 無効モード」（常時送信）の存在が UX 混乱を招いていた。「PTT は料金節約モードのオプトイン」という設計意図を簡素化
- **課金ランプ 3 色化（赤=送信中 / 黄=接続中待機 / 緑=停止）**  
  理由: Case D（PTT 離脱で接続維持）により state=RUNNING + audio_gate=false の状態が発生。2 色判定だと「送信していないのに赤」となり誤解を招く
- **両方 ON/OFF ボタン廃止（Q-SEM-5）**  
  理由: コールバック未発火バグ（#10）の修正コストよりボタン廃止の方が UX 簡素化
- **Case D 設計（PTT 離脱で接続維持）**  
  トレードオフ: 応答速度↑ vs OpenAI Realtime API 接続課金（最低料金）継続。監督確認で接続維持を選択
- **TCS 体制改善: L1 発注書 + report.md 物理ファイル必須化**  
  理由: QAちゃん指摘 (Task #32) で過去 4 件の発注書チェーン孤立が判明。今回 4 件の新規案件で TCS 順守

## Blockers, Gotchas & Workarounds

- **`run_e2e_smoke.py` が mock で動作**  
  原因: app.py を `--test-mode` で起動する設計 → `_TestModeSystem()` (mock) を使用  
  解決: `--real-api` フラグを追加する新規発注が必要（次セッション）
- **サブエージェントが Write を拒否（commissions/ への書き込み）**  
  原因: ツール制約  
  回避: テキスト報告 → 助監督が代筆して report.md を物理作成
- **`grep -i token` でハンドオーバー内の `keyboard` ライブラリ言及が引っかかる可能性**  
  原因: 「keyboard」は token 検査の偽陽性ではないが、注意
  回避: 実 API キー値は SPEC/handover に書かない
- **OpenAI Realtime API は接続維持で最低料金**  
  Case D 設計上、PTT 離脱しても route_b は RUNNING のまま → 接続課金継続  
  運用: 完全停止したい場合は「停止」ボタン or アプリ終了
- **VB-CABLE がドライバ名のみで判定すると検出失敗**  
  原因: `Win32_SoundDevice` はドライバ名のみ。エンドポイント名（CABLE Input/Output）は別途取得が必要  
  解決: pyaudiowpatch で取得（env_check.py 修正済）

## Key Learnings & Gotchas (長期記憶へ移行推奨)

- **TCS: L1 発注書を物理作成しないと孤立する** → メモリ `tcs-commission-chain.md` 保存済
- **発注書テンプレ** → メモリ `tcs-order-md-template.md` 保存済
- **「治った→治ってない」ループの根本原因**:
  - テスト ≠ 仕様検証（書いたケースのみ通る）
  - トートロジーテスト（テスト内で実装関数を直接呼んで結果 assert）禁止
  - RED 確認 MUST（わざとバグ入れて FAIL するか検証）
  - 既存テスト影響評価 MUST（件数前後比較）
  - 実機機能確認 MUST（TTS 等で実フロー）
  - 「PASS 報告」を鵜呑みにしない
- **DoD (Definition of Done)** → SPEC.md §22 に明記
- **codex の使い方**: profile 設定なしだとデフォルトモデル流れて事故、報告フェーズで stuck することあり
  - 大規模タスクで CPU 時間止まったら kill しても OK（ファイルは保存済）
  - 細かく分けて発注すべき（今回の教訓）
